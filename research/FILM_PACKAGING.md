# Native film resources

The reference film backend embeds its exact SPIR-V and float resources in `libscameraFilm.so`. The build compiles the readable `third_party/spektrafilm/shaders/*.comp` with pinned NDK `glslc -O`, then `tools/embed_film_reference.py` writes a binary, a hashed index, an assembly-backed C++ translation unit and a readable manifest in the CMake build directory. The binary uses aligned concatenation, not encryption. The generated manifest retains the original names, offsets, sizes and SHA-256 hashes for the owner.

The two original float files remain in the source tree under `app/src/main/assets/film-reference/` for regeneration and inspection. Gradle excludes that directory from the APK. The original generated profile-curve C++ source remains readable. Credits and licenses under `assets/film/` remain packaged.

The Android build defines `SCAMERA_EMBEDDED_FILM`. The Vulkan backend reads the same bytes from its native read-only section into the same vectors and GPU buffers. It performs no resource decompression, decryption or disk extraction per photograph. Existing JNI methods and image processing are unchanged. Without that definition, the original standalone renderer can still load loose resources from its normal file paths.

For a local build, Python 3 and the pinned Android NDK shader compiler must be available. CMake runs the generator when resource inputs change. The `embedded_film_manifest.json` build artifact can be used to recover any original resource from `embedded_film_data.bin`: slice `[offset:offset+bytes]` and verify its hash. Keep this manifest and unstripped native library locally for diagnosis; publish the stripped library in the APK.

This removes conveniently named loose shader/float assets and limits native exports to the JNI bridge. An APK can still be reverse engineered: embedded bytes, SPIR-V instructions and runtime buffers can be recovered. This is a practical obstacle to casual extraction, not a secrecy guarantee. Third-party attribution and applicable source availability remain intact.

Verification must compare every embedded resource byte and full film output, including film/paper/strength variants. Inspect the final APK to ensure `assets/film-reference/` is absent while licenses remain. Measure cold initialization, warm processing, memory and saving on the actual phone; host compilation alone proves neither performance nor device compatibility.

Local verification on OPPO PHY110/Adreno 750 (2026-11-02): the actual CMake library contains all 13 byte-identical resources, exports only the five JNI methods and has no debug symbol table in the QA APK. The loose assets are absent and credits remain. Two complete 12 MP scenes at film strength 0.5 match the earlier loose-resource build byte for byte. Full-strength Kodachrome 64 and Portra 400 with spatial effects, and Gold 200 without them, also match in all complete RGBA pixels across a cold process and two warm repetitions per profile. Evidence: `../evidence/vf-processing-20261102/film-hardening-review/full-post-parity.json` and `D:/burst/film-packaging-20261102/20261102-181718/receipt.json`.

A subsequent ABBA comparison used the same captured 12 MP input, explicit identical tone-cache switches and 24 complete post calls. Each profile had two cold-process samples and four warm samples per APK. Kodachrome 64 with spatial effects measured 7542/7594 ms cold and 5930/5981 ms warm; Gold 200 without spatial effects measured 2303/2365 ms cold and 1151/1133 ms warm (loose/embedded). Every complete RGBA output matched. These are neutral integration results, not a packaging speed claim: the newer APK also contains other accepted changes.

The receiver sampled its own memory after the unchanged post timer and before RGBA export. Maximum process-lifetime resident high-water marks were 1.438/1.424 GB for Kodachrome and 0.644/0.654 GB for Gold (decimal GB, loose/embedded). This is not an isolated per-shot peak or separate GPU-memory accounting. The earlier external PSS attempt failed after instrumentation exited and remains preserved as a failed attempt. Evidence: `../evidence/vf-processing-20261102/film-hardening-review/memory-postprobe/physical-final.json`. Final CI artifact inspection, save-time measurement and other GPUs remain separate; none of these checks satisfies the overall WhyCam speed gate.
