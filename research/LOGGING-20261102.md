# Single opt-in diagnostic log — 2026-11-02

The single `scamera_full_debug` master switch is OFF by default. When enabled it records the app's Java/JNI logcat and relayed worker events to `Documents/SCAMERA/Logs/SCAMERA_Log_YYYY-MM-DD.txt`. The main Application initializes the persisted switch after settings/module initialization and before previous-exit records, so settings/gallery/background entries are covered without opening CameraActivity. The `:scam` guard still starts only its minimal crash reporter. The previous permanent DCIM writer and separate Download debug/timing writers are retired; their existing files and stored owner settings are preserved. Existing debug/timing APIs route to this backend. Profiling alone does not enable a file log. The minimal startup crash report remains independently available, including when the optional log is OFF.

Scoped storage uses an app-owned MediaStore.Files row and append PFD; an unavailable public provider falls back to an explicitly reported actual private path. No root, READ_LOGS or all-files permission is requested. Android12/API31+ uses logcat `--uid`; Android8–11/API26–30 uses the supported current-process `--pid`. On those older systems, other own-UID processes' direct messages and previous-PID crash-buffer records are outside this collector; main-process JNI and worker stdout relays remain covered. Official AOSP versions and hashes are retained in the local platform audit.

One low-priority writer batches64Kcharacters/250ms, waits without periodic idle wakeups, and bounds pending input to4096records/512Kcharacters. Oversized records, queue overflow and storage-loss intervals have explicit markers. Logs rotate at8MiB with three generations per day and ten-day retention. Clear affects only the current log; size and sharing use the actual URI, with a FileProvider snapshot/read grant. Clear/share wait for a logcat FLUSH marker followed by the writer barrier. Startup now waits for that marker even before the collector assigns its process; failure resolves after a marked one-second timeout instead of silently returning a header-only snapshot.

The separate processing-stage ZIP switch writes `Documents/SCAMERA/Dumps` without enabling the master log. Existing worker heartbeat/completion parsing, in-memory reports, image metadata and frame algorithms are retained. Periodic synchronous diagnostic preference commits are replaced by opt-in asynchronous snapshots, while final/error report compatibility remains.
