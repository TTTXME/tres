## What the supplied GCam actually does

The installed package is `com.google.android.GoogleCamera`, version `6.1.021.Pit_6.3_Q`. The supplied APK's core library is byte-identical to the existing local GCam61 research copy. The current JPEG's HDRP v2 MakerNote was decoded, not inferred from thumbnail timing. `tools/decode_gcam61_makernote.py input.jpg output.txt` reproduces it. The output can include image payloads; do not publish the complete diagnostic dump.

- RAW input 4096×3072, packed RAW10; output 4094×3070, padded to 4096×3072.
- Sabre merge, 30 original frames, all 30 merged; no discarded sharpness frames.
- All payload exposures 166.6667 ms, ISO100; no SCAMERA-style long/extra-short exposure sequence.
- Capture 5244.81 ms; MergeShot 1065.02 ms; FinishShot 295.34 ms, including local tone mapping 97.97 ms. These named intervals must not be added indiscriminately because some are nested.
- Per-frame RAW sharpness is measured during capture. Postview arrives before the final JPEG. Logcat's second shot acquires RAW1 at 400208.787 and RAW30 at 400213.619; JPEG at 400215.012 (~1.39 s after the last RAW, ~7 s after tap). This is genuinely fast 30-frame Sabre; it is not a subsecond tap-to-file result.
- Eight worker threads; the diagnostic says CPU finish. A framework/fence `merge` Perfetto slice is not evidence for Sabre CPU/GPU stage time. The nondebuggable installed package denies Simpleperf profiling. A separate debuggable clone was prepared locally but installation requires the owner's screen-lock pattern; installation was cancelled and the original remains intact.

The decoder's xorshift/multiplier constants and HDRP/gzip layout were recovered from the supplied native routine at `0xc933d0` and decoder `0xc93540`. Tests cover truncation, gzip integrity/size limit, JPEG extraction and reversed extended-XMP chunks. Unsupported HDRP versions fail explicitly.

## Accepted implementation

1. Bionic `posix_spawn` with USEVFORK and CLOEXEC_DEFAULT on Android13+, dynamically resolved to retain API26 compatibility. Bionic owns all child setup. Signal mask, stdin, stdout/stderr and explicit passed descriptors are set with spawn actions. Unrelated descriptors close atomically under Bionic's policy. Existing fork launcher remains the post-capture fallback.
2. Existing worker prespawn enabled by default only where this API is available. Prespawn calls a **no-fork** entry point: unsupported API, launch error or different requested nice cannot silently fork the large camera process during capture. Existing standby fingerprint, ownership, timeout and post-capture fallback remain intact. `worker_prespawn 0` disables the default.
3. Rejection's pooled variance reuses the already computed q0 value. No changed equations, donor policy, grid spacing or protected `kHybMergeMain1` body.

System implementation reference: [AOSP Bionic spawn.cpp](https://android.googlesource.com/platform/bionic/+/249a7ae70e3e051d55696d5028f2c3600ab6a6f0/libc/bionic/spawn.cpp). No application code executes in the shared-address-space child.

## Investigated but rejected from this delivery

- GCam's32RAW-pixel tile spacing versus our16RAW-pixel spacing: `laStride16` materially changes the field/output. No known-truth/detail/motion quality proof sufficient to replace the finer default. Our existing pyramid, subpixel refinement and GPU path are retained.
- Cooperative KLT, added coarse level, donor variance cache and shared donor tiles: no repeatable end-to-end improvement, some worse or changed output. Patches and binaries preserved locally.
- Early zero-weight exits: 7523/37748736 half-RGB components differ (mostly1ULP; max absolute3.052e-5), no proved useful speed gain. Removed rather than labelled exact.
- Full-frame native Bitmap readback: independently verified12cases including RGBA/premultiplied alpha/pack state/failure paths, but redundant with PBO speed. Removed.

No invented new detail enhancement is enabled from these experiments. No reduced frame count, lower RAW resolution, weakened rejection or sharpening increase is used to obtain the reported speed. P424 window stairs remain a separate unfinished investigation. Device developer file is restored byte-for-byte to `ettr 1\n`; temporary APKs are local tests only. Final delivery must be the unmodified Actions artifact with its published checksum and release signer verified.
